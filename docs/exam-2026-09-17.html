Daily Knowledge Exam — 2026-09-17

100 scenario-based questions covering all 45 currently indexed knowledge articles, with two article-specific reasoning questions per article plus 10 cross-topic integration scenarios.

These questions are intentionally tied to specific mechanisms, packet paths, failure modes, and design choices from ccaiccie/knowledge. They are not vendor-name substitutions of a common template.

802.11k/v/r

1. A hospital voice handset loses 350–450 ms during every roam. A capture shows most of the delay is active scanning across many 5 GHz channels; once the target AP is chosen, FT authentication and reassociation finish in under 50 ms. Which feature addresses the dominant delay?

Explanation: The evidence isolates candidate discovery as the bottleneck. 802.11k reduces the scan search space by supplying neighboring BSSIDs/channels; 802.11r already appears healthy.

2. A controller sends an 802.11v BSS Transition Management Request recommending AP-2 because AP-1 is overloaded. The station ignores it and stays on AP-1. No disassociation-imminent flag is set. What should you conclude first?

Explanation: Ordinary BTM is advisory. The infrastructure can recommend a target, but the client normally retains the final roaming decision.

DNS64/NAT64

3. An IPv6-only client receives AAAA 64:ff9b::c000:020a for an IPv4-only server, but packets die at the edge. DNS resolution is correct. What must exist on the forwarding path?

Explanation: DNS64 only synthesizes an IPv6 destination. A NAT64 translator must recognize the same prefix and translate the flow to IPv4.

4. External DNS64 synthesizes with 64:ff9b::/96, but the Palo Alto NAT64 rule expects a different prefix. What operational symptom follows?

Explanation: DNS64 and NAT64 must agree on the translation prefix. Prefix mismatch breaks the control-plane/data-plane handoff.

OIDC

5. A web RP accepts any signed JWT from its IdP and never checks aud. An access token intended for api.example.com is presented to the RP and accepted as a login token. Which validation failure enabled this?

Explanation: Signature validity is not enough. The RP must validate that the token type and audience are intended for that client.

6. An attacker steals the authorization code from a browser redirect but does not know the original code_verifier. Which mechanism is specifically designed to make the stolen code useless?

Explanation: PKCE binds the authorization code to the client instance through the code_verifier/code_challenge relationship.

Perimeter Design

7. A dual-firewall Internet edge reconverges routing in 700 ms, but every established session resets during failover because the standby has no synchronized session state. Which design area was under-specified?

Explanation: Routing convergence is only one timeline. Stateful HA also requires session/state synchronization and explicit recovery expectations.

8. The HLD says Internet → firewall → DMZ reverse proxy → app, but the LLD contains no return-path, NAT, or failure-state detail. Why is that a production risk?

Explanation: A usable LLD must define routing, NAT, policy, session behavior, and failover—not just the forward architecture picture.

DNSSEC

9. A validating resolver returns SERVFAIL after a KSK rollover. dig +trace shows the parent DS points to a digest that no longer matches the child's active KSK DNSKEY. How will validation classify the child?

Explanation: A broken DS→DNSKEY chain is an authenticated-chain failure, so the response becomes Bogus rather than merely Insecure.

10. Signed responses work over TCP but intermittently fail over UDP through one firewall path, especially for DNSKEY answers. What should you investigate?

Explanation: DNSSEC increases response size, which makes EDNS, fragmentation, MTU, and TCP fallback operationally important.

MACsec

11. Small frames cross a MACsec-protected carrier Ethernet handoff, but near-MTU frames drop only after MACsec is enabled. What is the first data-plane check?

Explanation: MACsec adds Ethernet overhead. Paths already near MTU can begin dropping larger frames when protection is enabled.

12. Both sides are configured for AES-GCM, but MKA never forms a secure channel. One side uses CKN WAN-A and the other WAN-B. Why is this significant?

Explanation: MKA peers need compatible CAK/CKN association parameters before SAKs and secure associations can be established.

PRP

13. A DANP transmits every Ethernet frame on LAN A and LAN B. LAN A fails completely, yet the control application sees no reconvergence pause. What explains the zero-recovery behavior?

Explanation: PRP duplicates every frame across independent LANs; losing one copy does not require a convergence event.

14. A single-attached legacy PLC must participate in a PRP domain without native dual-LAN support. Which component adapts it?

Explanation: A RedBox connects SAN devices to the PRP network and handles replication/duplicate-discard functions for them.

FortiAP Dynamic VLAN

15. RADIUS Access-Accept returns Tunnel-Type=VLAN, Tunnel-Medium-Type=IEEE-802, and Tunnel-Private-Group-ID=220. Authentication succeeds, but the client lands in the SSID default VLAN. What should you validate first?

Explanation: Successful authentication does not prove VLAN placement. The FortiAP/FortiGate policy must consume the attributes and map them to a reachable VLAN.

16. A bridge-mode FortiAP correctly assigns VLAN 330, but DHCP never answers. The FortiGate is not tunneling user data. Which dependency is most likely missing?

Explanation: In bridge mode, user VLANs leave the AP on the physical uplink, so the switching path must carry the dynamically assigned VLAN.

IOS XE Route Leaking

17. VRF BLUE can reach a shared DNS server leaked from global routing, but replies from the server never return to BLUE. What is the most likely architectural mistake?

Explanation: VRFs have separate RIB/FIB domains. Shared services require deliberate bidirectional reachability.

18. Broad redistribution between VRF BLUE and RED causes a leaked prefix to feed back into its original protocol and oscillate. What control was missing?

Explanation: Redistribution across routing domains needs filtering, tagging, and loop-prevention policy—not just mutual redistribution statements.
